B. Convert ExpressionEvaluator's internal intermediate buffers
   ExpressionEvaluator has ~30+ transient pmr_vector<...> scratch allocations
   across the _evaluate_* paths (arithmetic, logical, case, in, predicate,
   cast, extract, etc.). They use the default heap allocator today.
   - Each call is small relative to the final values/nulls vectors returned to
     the caller (which ARE now on _mr).
   - Only worth doing if per-operator delta JSON shows a Projection / TableScan
     / JoinHash with a non-zero gap between its measured delta and the sum of
     its segment payloads.
   - Mechanical edit: route each `pmr_vector<X>{}` / `pmr_vector<X>(n)` site
     through `PolymorphicAllocator<X>{_mr}`. No signature changes.


Intentionally skipped (low value)
---------------------------------
- UnionPositions: operates on existing PosLists; ReferenceMatrix / VirtualPosList
  intermediates are small per-row metadata.
- UnionAll: just chains chunks; no significant new allocations.
- JoinHash residual: `hash_tables` outer vector, `jobs` vectors, inner SmallPosList
  overflow via _memory_pool / _monotonic_buffer (kept on thread-local unsync pool
  for build-phase perf).
- AggregateHash residual: per-AggregateResultContext monotonic_buffer is upstream
  to runtime_exec_resource() but not the captured _runtime_mr — under Greedy
  strategy a per-context buffer constructed mid-query could land on a different
  pool than the operator's other state if a pool just filled. Acceptable.


Verification pattern after each conversion
------------------------------------------
1. Build.
2. In Console: `setting track_per_op_mem on` and pick a strategy
   (`setting mem_strategy local|remote`).
3. Run with a SINGLE worker (concurrent operators contaminate per-op deltas).
4. Run a representative TPCH query (Q1 for aggregate, Q6 for sort,
   Q4 for projection, any q with WHERE for table_scan/validate).
5. Inspect query_exec_info_<n>.json:
   - "memory_deltas" — per-pool total for the whole query.
   - "operator_memory_deltas" — per-operator breakdown. Any operator showing 0
     on the runtime pool but >0 on heap (resource_id 0) is unconverted.
6. Switch strategy to Remote, rerun, confirm pool 3 takes the allocations.
7. Switch to Greedy, rerun, confirm hard-stop behavior on capacity exhaustion.
